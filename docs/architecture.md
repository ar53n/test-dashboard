# Архитектура

## Обзор

```
┌──────────── браузер ─────────────┐        ┌────────── server/ (Node 24) ──────────┐
│ React UI (widgets, features)     │        │ http.ts   GET /api/org-tree, /health  │
│   ▲ useOrgModel()                │        │ store.ts  in-memory дерево,           │
│ TanStack Query cache             │  HTTP  │           epoch + revision            │
│   ▲ fetchOrgModel (queryFn)      │ ─────► │ data/generate.ts  детерминированный    │
│ fetch → zod → buildIndex →       │ ◄───── │           генератор (80 узлов)         │
│         computeAggregates        │        └───────────────────────────────────────┘
└──────────────────────────────────┘
```

В dev-режиме Vite проксирует `/api` на `localhost:3001` (`vite.config.ts`).

## Слои клиента

Структура в духе feature-sliced: зависимости направлены только вниз.

| Слой | Путь | Что лежит | Может импортировать |
| --- | --- | --- | --- |
| app | `src/app` | корень приложения, провайдеры (QueryClient, тема) | всё |
| widgets | `src/widgets` | компоновка страницы (`Dashboard`) | features, entities, shared |
| features | `src/features` | пользовательские сценарии (`org-tree`) | entities, shared |
| entities | `src/entities/org` | модель оргструктуры: схема, индекс, агрегаты, запрос, базовые UI-элементы | shared |
| shared | `src/shared` | HTTP-обёртка, ошибки, тема, общие UI-компоненты | — |
| contract | `shared/contract.ts` | типы и константы протокола, общие для клиента и сервера | — |

Абсолютные импорты: `@/…` → `src/…`, `@shared/…` → `shared/…` (алиасы в `vite.config.ts`, `paths` в `tsconfig.app.json`).

## Поток данных: от API до UI

1. **Компонент** вызывает `useOrgModel()` (`src/entities/org/api/orgTreeQuery.ts`). Все потребители используют один query key, поэтому запрос один на всех.
2. **TanStack Query** решает, нужен ли запрос: данные свежие 5 секунд (`staleTime`), после этого показываются из кэша и перепроверяются в фоне (stale-while-revalidate).
3. **`fetchOrgModel`** выполняет условный запрос:
   - берёт версию текущей модели из кэша и отправляет `If-None-Match: "<epoch>-<revision>"`;
   - `cache: 'no-store'` отключает HTTP-кэш браузера, иначе браузер сам превратил бы 304 в 200 и клиент не узнал бы, что данные не изменились;
   - на 304 или на ответ с той же/более старой версией возвращает модель из кэша — без разбора JSON и без агрегации.
4. **Валидация** (`schema.ts`, zod): ответ, не соответствующий контракту, превращается в `ApiError('validation')` и не попадает в кэш.
5. **Построение модели** (`orgModel.ts`): `buildIndex` проверяет целостность дерева (уникальность id, существование родителей, отсутствие циклов), `computeAggregates` один раз считает агрегаты всех узлов.
6. **Кэш** хранит готовую `OrgModel`. `structuralSharing` сравнивает версии: снимок той же или более старой ревизии не заменяет модель, поэтому нет лишних ререндеров.
7. **UI** читает модель: дерево берёт индекс, шапка — агрегаты корней.

## Надёжность

| Ситуация | Поведение |
| --- | --- |
| Первая загрузка | skeleton (`LoadingState`) |
| Сеть недоступна / 5xx | 2 повтора с экспоненциальной задержкой, затем `ErrorState` с кнопкой «Повторить» |
| Соединение оборвалось после заголовков, при чтении тела | сетевая ошибка: те же повторы, что при недоступной сети |
| Невалидный JSON, ответ не по схеме или битая иерархия | `ErrorState` со списком проблем, без повторов |
| Пустой массив | `EmptyState` |
| Фоновое обновление упало, данные есть | данные остаются на экране, сверху баннер с «Повторить» |
| Размонтированы все потребители во время запроса | `AbortSignal` отменяет fetch; сервер в сценарии `slow` снимает таймер |

Демо-сценарии для проверки: `?scenario=error|empty|invalid|slow` в адресе страницы пробрасывается в API.

В dev-режиме StrictMode монтирует компоненты дважды, поэтому в Network виден отменённый первый запрос и следом успешный. В production-сборке запрос один.

## Сервер

`server/` — отдельный npm workspace без сборки: Node 24 запускает TypeScript напрямую (type stripping), поэтому код использует только стираемый синтаксис (`erasableSyntaxOnly`).

- `store.ts` — состояние в памяти. `epoch` генерируется при старте процесса, `revision` растёт при изменениях.
- `http.ts` — маршруты на `node:http`, ETag и заголовки версии, 304 на совпадающий `If-None-Match`. Некорректный адрес запроса получает 400, непредвиденная ошибка обработчика — 500; процесс в обоих случаях продолжает работать.
