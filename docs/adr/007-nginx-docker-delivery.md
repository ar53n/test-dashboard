# ADR 007. Поставка: Docker Compose, nginx, бюджет бандла

**Статус:** принято · этап 4

## Контекст

- `docker-compose up` поднимает клиент и сервер, конфигурация через `.env`.
- nginx проксирует API и раздаёт статику со сжатием gzip.
- Бандл не больше 200 КБ gzip.
- Проект должен запускаться с чистого checkout без `.env` и без AI-ключа.

## Решение

**Два образа, контекст сборки — корень репозитория** (нужны lock-файл workspace и общий `shared/`):

- `server/Dockerfile` — `node:24-alpine`, `npm ci --workspace server --omit=dev`: в образе только `ws` и `zod` (8 МБ `node_modules`). TypeScript исполняется напрямую, сборки нет. Процесс работает от пользователя `node`.
- `Dockerfile` (клиент) — multi-stage:
  1. `npm ci`, затем `npm run build` (проверка типов и Vite);
  2. `npm run size` — сборка падает при превышении бюджета;
  3. `npm run compress` — рядом с файлами `.gz`;
  4. статика копируется в `nginx:1.29-alpine`.

**Compose.** Все переменные заданы через интерполяцию с безопасными значениями по умолчанию (`${AI_API_KEY:-}`, `${CLIENT_PORT:-8080}`). Compose сам читает `.env` из корня, если он есть, и не требует его. Порт клиента публикуется только на `127.0.0.1` (`CLIENT_BIND`, для доступа из сети — `0.0.0.0`): включённый AI-поиск тратит ключ провайдера, и случайно открытое в сеть демо не должно делать это по чужим запросам. Сервер наружу не публикуется (`expose`). Клиент стартует после `healthcheck` сервера (`/api/health`).

**nginx** (`nginx/default.conf.template`, адрес API подставляет envsubst официального образа):

| location | Поведение |
| --- | --- |
| `= /api/ai-search` | прокси на сервер с `limit_req`: 10 запросов в минуту с IP, всплеск до 5; сверх — JSON 429 `rate_limited` с `Retry-After`, как у сервера |
| `= /api/live` | `proxy_http_version 1.1`, `Upgrade`/`Connection` через `map`, таймауты 1 ч (heartbeat раз в 15 с) |
| `/api/` | прокси на сервер, `proxy_read_timeout 30s` |
| `/assets/` | `Cache-Control: public, max-age=31536000, immutable` — имена с хэшем |
| `/` | SPA fallback на `index.html`, `Cache-Control: no-cache` |

Сжатие: `gzip_static on` отдаёт заранее сжатые файлы без работы CPU на запрос. `gzip on` сжимает на лету ответы API и файлы без `.gz`.

**Бюджет бандла** — `scripts/check-size.mjs`: сумма gzip (уровень 9) всех JS и CSS в `dist` ≤ 200 КБ, лимит меняется через `BUNDLE_LIMIT_KB`. Сейчас около 126 КБ: React, styled-components, TanStack Query и zod, без UI-библиотек.

## Найдено при проверке

**nginx при gzip-сжатии превращает ETag в слабый** (`W/"epoch-rev"`). Клиент дашборда строит `If-None-Match` сам из заголовков версии и не пострадал бы. Но HTTP-клиент, который возвращает полученный ETag как есть, никогда не получал бы 304. Сервер теперь сравнивает ETag слабо (RFC 9110): `W/` игнорируется, поддерживаются список значений и `*`.

## Найдено при аудите

**AI-маршрут не ограничивал расход.** Любой клиент с доступом к порту мог сколько угодно раз вызывать провайдера за счёт серверного ключа, а compose публиковал порт на всех интерфейсах. Теперь порт по умолчанию слушает только `127.0.0.1`, nginx ограничивает AI-поиск по IP, сервер держит общий лимит частоты и параллельности (ADR 006). Авторизации нет: в демо нет пользователей.

## Альтернативы

- **`env_file: { path: .env, required: false }`** — вариант из плана. Работает, но переменные окружения контейнера тогда задавались бы в двух местах (`env_file` и `environment` с умолчаниями). Интерполяция даёт одно место и те же гарантии без `.env`.
- **Отдельный контейнер для статики и Node-прокси.** Лишний процесс: nginx делает и то, и другое.
- **Brotli.** Лучше сжимает, но в официальном `nginx:alpine` нет модуля; gzip достаточно для бюджета.
- **Сборка сервера в JS (tsc/esbuild).** Node 24 исполняет стираемый TypeScript напрямую; сборка добавила бы шаг без выгоды.

## Последствия

- `docker compose up --build` на чистой копии работает без `.env`; AI-поиск выключен и честно об этом сообщает.
- Ключ AI передаётся только в контейнер сервера; в клиентскую сборку и nginx он не попадает.
- Чтобы открыть демо в сеть, нужно явно задать `CLIENT_BIND=0.0.0.0`. Для реального размещения AI-маршрут нужно закрыть авторизацией: лимиты ограничивают расход, но не доступ.
- Изменение `nginx`-шаблона или статики требует пересборки образа клиента.
