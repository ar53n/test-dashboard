# ADR 003. Производная модель и версия состояния в кэше запроса

**Статус:** принято · этап 1

## Контекст

- Агрегаты должны считаться один раз после загрузки и мемоизироваться.
- Кэш должен инвалидироваться только при реальном изменении данных.
- На этапе 3 патчи будут менять модель точечно, а запоздавший HTTP-ответ не должен откатывать уже применённые изменения.
- Состояние сервера живёт в памяти: после рестарта номер ревизии повторяется для других данных.

## Решение

1. **В кэше лежит готовая `OrgModel`** (индекс + агрегаты), а не сырой массив. `queryFn` строит модель один раз; компоненты только читают.
2. **Версия = `(epoch, revision)`.** Сервер генерирует `epoch` при старте и отдаёт версию в `ETag`, `X-Org-Epoch`, `X-Org-Revision`. Ревизии сравниваются только в пределах одного epoch.
3. **Условный запрос в `queryFn`.** Клиент сам отправляет `If-None-Match` с версией модели из кэша (`cache: 'no-store'`, чтобы браузер не подменял 304 на 200). На 304, а также на 200 с той же или более старой ревизией `queryFn` возвращает модель из кэша, не разбирая тело.
4. **`structuralSharing` как функция сравнения версий** (`pickCurrentModel`): новая модель заменяет старую только при более новой ревизии или другом epoch.

## Альтернативы

- **Сырой массив в кэше + `useMemo` / `select` для агрегатов.** `select` и `useMemo` пересчитывают при каждом новом ссылочном значении и в каждом потребителе; ни то, ни другое не даёт точечного обновления на этапе 3.
- **Положиться на HTTP-кэш браузера (`no-cache` + ETag).** Браузер сам ответит 200 из кэша на 304, но JS об этом не узнает: тело снова разбирается и агрегируется.
- **Только `revision` без epoch.** Проще, но после рестарта сервера возможен ложный 304 и отброшенный «такой же» снимок с другими данными.
- **Сохранять состояние на диск для монотонной ревизии.** Требует хранилища, которое в задании не нужно.

## Последствия

- Модель содержит `Map`, поэтому стандартный `structuralSharing` отключён и заменён сравнением версий.
- `queryFn` читает кэш через `client.getQueryData` — небольшая связанность запроса со своим же кэшем, зато повторная агрегация исключена.
- Демо-сценарии без версии (`version: null`) всегда заменяют модель — они нужны только для ручной проверки состояний.
